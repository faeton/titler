# Titler — следующий этап: исполнители, публичный API, серии, обложки, публикация

2026-10-25. Продолжение [PLAN-v2.md](PLAN-v2.md) после переноса на мак ([mac.md](mac.md)).
Ресёрч: [cloud ASR](../bench/REPORT-cloud-asr.md), [облачные исполнители и шлюз](../bench/REPORT-cloud-exec.md),
[площадки публикации](../bench/REPORT-publishing.md).

## Зачем

Один веб-интерфейс, а где выполняется каждый шаг — выбирается: n5, мак, облачный API, позже
телефон. Готовый ролик режется на части под лимиты площадок, получает обложку и уходит в
публикацию без ручной пересборки. Главная метрика прежняя: сколько ручной работы между
загрузкой и опубликованным роликом.

Не цели этого этапа: облачный рендер (ни один сервис не умеет ASS/libass), полный перенос
конвейера на телефон, публикация в чужие аккаунты.

## 1. Исполнители шагов (одна оболочка, много вариантов)

**Шаги:** ingest/proxy, analyze, asr, align, enhance, render, cover, publish.

**Исполнитель** (`provider`) — кто выполняет шаг:

| вид | пример | транспорт |
|---|---|---|
| local | воркеры этого сервера (как сейчас) | JSON-lines (`docs/worker-protocol.md`) |
| remote runner | другой titler по tailnet (n5 ↔ m3max) | тот же протокол поверх HTTP, файлы по подписанной ссылке |
| cloud API | ElevenLabs, Gemini, Soniox, OpenAI, Claude | адаптеры из `bench/cloud/` → новая роль воркера `cloud` |
| cloud GPU | свои модели на Modal (позже) | тот же протокол, медиа по presigned URL |
| phone | офлайн-черновик в приложении (будущее, §6) | — |

- `/api/providers` уже есть; расширить до записи на шаг: `step`, `kind`, `models`,
  `enabled/reason`, `costPerMin` (оценка), `dataLeavesBox` (данные уходят наружу), `wordTimestamps`.
- Выбор: глобальные дефолты в настройках + переопределение в проекте. Параметры задания
  хранят provider + model; ключ артефакта включает их (для ASR уже так).
- UI: у каждого шага селектор исполнителя с ценой/минуту и пометкой «уходит в облако».
  Облачный исполнитель без ключа виден, но выключен с причиной (как сейчас).

**Что подключать первым (по ресёрчу):**

| шаг | локально (по умолчанию) | внешний вариант | заметка |
|---|---|---|---|
| asr | faster-whisper turbo | ElevenLabs Scribe v2 ($0.0045/мин), Soniox, Gemini | адаптеры готовы, нужны ключи |
| review | — | Claude (текстовый проход по спорным местам) | готово в `bench/cloud` |
| align | w2v + GigaAM | ElevenLabs Forced Alignment (русский есть, `loss` по слову) | как перекрёстная проверка |
| enhance | MF2 / DFN3 | ElevenLabs Voice Isolator ($0.12/мин, только голос → фон = остаток); AudioShake (настоящие стемы) | проверить 48 кГц и точность вычитания |
| свои модели в облаке | — | Modal L4, ≈ $0.01 на минуту видео | когда нужно без n5 и мака |
| render | ffmpeg + libass | нет | облачные рендеры не умеют ASS |

## 2. Публичный API (de1)

Сейчас сервер без авторизации и виден только в tailnet. Чтобы им пользовались приложение и
площадки (Instagram забирает видео по публичной ссылке), нужен вход из интернета.

**Шаг A (минимум):** на de1 Caddy с авто-TLS → прокси по tailnet на сервер n5 (или мака).
Дома ничего не слушает интернет. В сам сервер добавить:
- вход владельца: сессия по cookie (пасскей или длинный токен);
- ключи устройств для приложения и скриптов: хешированные, отзываемые, с именем;
- подписанные временные ссылки на артефакты (`/s/<token>`, TTL минуты-часы) — для
  `video_url`/`cover_url` Instagram, AudioShake, Modal;
- CORS, лимиты запросов.
Загрузка уже чанками по 4 МБ → не упирается в лимит 100 МБ Cloudflare, но загрузку через
Cloudflare не пускаем вообще (только прямой Caddy).

**Шаг B (позже):** координатор на de1 с очередью; n5 и мак сами забирают задания по tailnet
(pull). Нужен, когда исполнителей станет несколько и они будут включаться/выключаться.

## 3. Серии (нарезка на части)

**Пресеты длины части** (с запасом от лимитов):

| площадка | макс. часть |
|---|---|
| IG Stories | 59 с |
| IG Reels, YT Shorts, TikTok | 179 с |
| FB Reels | 89 с |
| Telegram | без нарезки (лимит по размеру файла) |
| своя | любое значение |

**Алгоритм** (чистая функция в `packages/core`, с тестами):
1. Число частей `n = ceil(длительность / макс)`; целевые точки — равные доли.
2. Кандидаты на разрез — паузы между словами ≥ 300 мс; вес выше у конца предложения,
   границы абзаца и тишины по VAD. Внутри слова не резать никогда.
3. Выбор разрезов динамикой: минимизировать отклонение от целей + штрафы, жёсткое условие
   «каждая часть ≤ макс». Окно поиска ±15 % от цели.
4. Хвост короче ~12 с — перераспределить (или влить в предыдущую часть, если влезает).
5. Если пауз нет — разрез на самом длинном промежутке между словами в окне.
6. Опция: повтор последних ~0.5 с в начале следующей части.

**Нумерация «1/3»:**
- Опция в настройках серии; показывается, если частей **больше двух** (порог настраиваемый,
  по умолчанию 3 — как сказано в задаче).
- Формат «1/3» или «Часть 1 из 3»; верх кадра внутри безопасной зоны, первые 2–3 с или всю
  часть; рисуется через тот же компилятор субтитров → одинаково в превью и в ASS.
- В подпись к публикации автоматически «(1/3)».

**Рендер:** каждая часть — отдельный артефакт с диапазоном `[t0, t1]` в исходном времени
(точный `-ss/-to`, аудиовариант обрезается так же, субтитры разрезаются по границе и
пересчитываются от нуля). Проверка каждой части: длительность ≤ макс, A/V синхрон.
Имена `…_p1of3.mp4`, кэш по частям, прогресс по частям.

**UI (экран «Экспорт»):** выбор площадки → полоса времени с разрезами (перетаскиваются,
прилипают к паузам), длительность каждой части (красным, если > макс), переключатель «1/3».
План серии свой у каждой площадки (Stories и Reels режутся по-разному).

## 4. Обложки (превью)

- Выбор кадра на экране «Экспорт»: прокрутка по прокси, шаг по кадрам; 3–5 предложенных
  кадров (резкость, без смаза) — в первой версии просто равномерно + самый резкий.
- Наложения на обложку: заголовок (опционально), бейдж «1/3» для серии.
- Направляющие: 9:16 целиком, центральный кроп сетки профиля IG (~3:4), 16:9 для обычных
  видео YouTube.
- Кадр берётся из исходника (не из прокси) с тем же кадрированием → JPEG 1080×1920 (≤ 8 МБ),
  для YouTube-видео 1280×720.
- Доставка по площадкам: IG Reels — `cover_url` (у Stories обложки нет); YouTube —
  `thumbnails.set` (для Shorts через API, скорее всего, нельзя); TikTok —
  `video_cover_timestamp_ms`; Telegram — `cover`.

## 5. Публикация (уточнённый P7)

Порядок по сложности подключения:
1. **Telegram** — бот в канале; ≤ 50 МБ (или локальный Bot API server до 2 ГБ).
2. **YouTube** — свой канал, загрузка файлом, плейлист на серию. OAuth-экран перевести в
   «In production» (в «Testing» токен живёт 7 дней). Первой загрузкой проверить, не
   блокируется ли она как private.
3. **Instagram** — аккаунт перевести в **Creator** (личный API не поддерживает); Meta-приложение
   в dev-режиме, аккаунт — тестер приложения (без App Review); вход через Instagram Login;
   видео отдаём подписанной ссылкой с de1 (§2). Сначала Reels, потом Stories.
   «Link a Reel» для серии — только в приложении, UI напоминает.
4. Facebook Reels — только если есть Page. 5. TikTok — последним (аудит, без него только приватно).

Каждая площадка — отдельное задание со своим состоянием и удалённым id; повтор не
дублирует успешную публикацию (как в `spec-workflow.md`). Серия публикуется по порядку частей.

**Что нужно от владельца:** перевести IG в Creator; создать Meta-приложение; проект в Google
Cloud + подтвердить канал по телефону; бот Telegram + права в канале; ключи ElevenLabs /
Anthropic (и по желанию Gemini/Soniox).

## 6. Приложение iOS — на будущее (не сейчас)

Тонкая оболочка: интерфейс тот же веб (WKWebView), нативно только то, чего не даёт Safari:
- share extension «Поделиться → Titler» из «Фото» и Meta View;
- фоновая загрузка больших роликов (`URLSession` background);
- push «готово», сохранение в «Фото»;
- **публикация через родное приложение Instagram** (поделиться в Stories/Reels из приложения) —
  возможно, без перевода аккаунта в Creator и без Meta-API. Проверить, что это даёт для Reels.
- офлайн-черновик: быстрая расшифровка на телефоне (WhisperKit) и простой рендер; сначала
  проверить WhisperKit на трёх клипах (держит ли английский хвост 34238).

Начинать после §2 (нужны ключи устройств и публичный адрес).

## Мои решения (проверь)

- Порог «1/3» — по умолчанию при 3+ частях (так прочитал «если больше двух частей»).
- Пресеты длины с запасом в 1 с от лимита (59 / 89 / 179).
- Минимальная длина части ~12 с; ниже — перераспределение.
- Шлюз — свой Caddy на de1, не Cloudflare Tunnel (лимит 100 МБ, загрузка видео) и не Funnel.
- Сначала шаг A (прокси на n5), координатор с pull-воркерами — позже.
- Модели в облаке — Modal (проще всего развернуть Python, $30/мес бесплатно), RunPod запасной.
- Рендер остаётся локальным везде.

## Проверить при подключении

ElevenLabs: цена alignment, частота выхода Isolator (48 кГц?), качество фона вычитанием.
Instagram: 100 или 50 постов/сутки; Stories на Creator; rupload с Instagram Login.
YouTube: блокировка private у непроверенного проекта; обложки Shorts через API.
